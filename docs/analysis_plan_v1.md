# Stage 1 Analysis Plan v1

- Date: 2026-10-28
- Status: committed after the pilot run and before the main run. Fixed before any main-run output exists.
- Scope: this plan specifies how Stage 1 data are produced and analysed. It supplements the sealed files (tag `seal-v1`) and does not modify them. Where this plan is silent, `scoring_rubric.docx` and `stage1_scoring_protocol.md` apply.

## 1. Inputs
- Coder inputs are derived from the sealed coding lists by `python -m subtext prepare`. Each model call receives only the interviewee details and the passage, formatted by `prompts/v1/user_template.txt`. Segment id, version, list and code are never sent.
- Prompt version: v1 (`prompts/v1/`), unchanged after the pilot. The SHA-256 of each prompt file is stored in every output record.

- Backend: Ollama 0.40.11, local, on one machine (MacBook Pro, Apple M5, 16 GB).
- Thinking mode on; the reasoning trace is archived with each output.
- Sampling: temperature 0.6, top_p 0.95, top_k 20, min_p 0 (Qwen3 thinking-mode settings recommended in the official model card). Context window 8192 tokens; generation capped at 6144 tokens.
- Seeds: run k uses seed k (k = 1..5) for every segment and both models. Pilot runs used seeds 901 and 902; the determinism check used seed 999. In the pilot, two calls with the same model, segment and seed produced identical answers and reasoning traces.
- Order: run-major (run 1 for all 48 segments, then run 2, and so on), 8B before 14B.
- Configuration file: `config/main.yaml`. Outputs: `runs/main/`.

## 3. Output handling
- A response is schema-valid if it parses as JSON, satisfies `prompts/v1/output_schema.json` (checked by the pipeline after parsing, whatever Ollama enforces) and ends with `done_reason = stop`.
- Retry rule: a schema-invalid response is re-requested with seed + 100, then seed + 200. All attempts are archived. The analysis uses the schema-valid attempt. A cell (model × run × segment) with no valid attempt after three tries is treated as missing and reported; it is not replaced by another run.
- Schema-violation rate is computed on first attempts.
- Form deviations (labels outside 2–6 words, quotes over 30 words) are recorded and reported as a compliance measure. They do not trigger a retry and do not affect scoring.
- Transport errors (connection, timeout) are not model output; the call is repeated on resumption.

## 4. Evidence check
Each quote is compared with its passage after typographic normalisation (quotation marks, apostrophes, dashes, ellipsis character, whitespace). Tiers, in order of application:
1. verbatim: found as one span, case-sensitive.
2. loose: found after case-folding, trimming edge punctuation and a leading speaker label.
3. elided: contains "..." and every fragment is found in order.
4. stitched: two or more sentences of three or more words, each found, but not as one span in the given order.
5. near: best word-window similarity of at least 0.90.
6. absent: none of the above.

- Fabricated-evidence rate = absent quotes / all quotes in schema-valid responses, by model.
- Stitched and near quotes are reported separately. Quotes taken from interviewer lines are counted separately.

## 5. Scoring
- Primary scoring set: run 1 of each model on all 48 segments (96 responses), scored blind by Xiner Liu under the protocol.
- Second scoring: Prof. Xiaoran Hu scores a random 20% of the primary set (20 responses), drawn by script with a recorded seed.
- Secondary scoring (optional, time permitting): a random sample of responses from runs 2–5, drawn by script with a recorded seed, scored and reported separately. Selection never depends on similarity or any instability measure.
- Calibration: the worked examples in Section 6 of the rubric and the 12 pilot responses. Pilot responses are excluded from all results.
- Blinding: the scoring sheet shows a random `response_id` only. The key linking `response_id` to model and run is generated by script; its SHA-256 is committed at generation, and the key itself is kept out of the repository until all scoring is complete.

### 5.1 Rubric application note (E segments)
The neutral prompt asks what the interviewee is communicating; it does not ask coders to contrast what is said with what is meant. For E segments, a reading therefore counts as claiming a mismatch (Step 2 of the rubric) if it attributes to the speaker a feeling or evaluation that is incompatible with `surface_meaning` and corresponds to a core component of `intended_meaning`, provided it does not misstate the literal content. Such a reading proceeds to Step 4. Explicit contrast is not required. Rules for C segments are unchanged. This note is confirmed with the second scorer at calibration; if it is changed, the change is recorded in a separate dated deviation file before formal scoring.

## 6. Instability measures
Computed for each model × segment from all five runs, without reference to scores:
- Semantic dispersion: mean pairwise cosine distance between embeddings of the `interpretation` field (10 pairs). Embedding model: `nomic-embed-text` via Ollama; its digest is logged at computation.
- Tone disagreement: 1 − share of the modal tone.
- Confidence: standard deviation and mean of self-rated confidence.
- Cross-model distance (per segment): mean cosine distance over the 25 pairs of 8B × 14B interpretations.

## 7. Outcomes and analyses
- Primary outcome per model × segment: the run-1 category. Interpretive error = N or M on E segments, O on C segments. A sensitivity analysis also counts P as an error.
- Summary metrics as in Section 8 of the rubric, by model, layer (A–D) and level (L1–L3).
- RQ1: E versus C segments, paired by `pair_id` (24 pairs per model), on (a) interpretive error and (b) each instability measure. Effect sizes with 95% bootstrap confidence intervals; McNemar's test for (a), Wilcoxon signed-rank test for (b).
- RQ2: heat map of mean read score (E) and over-interpretation rate (C) by layer × level, per model, with cell counts shown.
- RQ3: whether each instability measure and mean confidence predicts run-1 interpretive error across the 48 segments, per model and pooled. AUC with 95% bootstrap confidence interval; calibration plot of confidence against error rate.
- Sensitivity: results with and without the three medium-confidence segments (rubric 5.5); shortcut check as in rubric Section 8.
- Agreement: Cohen's kappa as in rubric Section 9, on pre-discussion scores.
- Bootstrap: 2,000 resamples, seed 20261029. Tests are two-sided. With 24 pairs and 48 segments per model, all inferential results are reported as exploratory, with effect sizes and intervals given priority over p-values.

## 8. Deviations
Any departure from this plan is recorded in a separate, dated file in `docs/`. This file is not modified after commit.
